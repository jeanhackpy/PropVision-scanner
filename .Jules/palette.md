## 2025-05-15 - Interactive Accessibility in Map and Bottom Sheet Components
**Learning:** Adding `tabIndex={0}` and `role="button"` or `role="application"` to non-interactive elements (like map containers or decorative handles) requires careful management of focus states. Using `focus-visible:outline-none` without an alternative like `focus-visible:ring` creates an accessibility regression where keyboard users lose their location. Furthermore, `aria-label` descriptions must strictly match the implemented keyboard handlers (e.g., don't suggest arrow keys if only Enter is supported).
**Action:** Always pair focus-removal classes with high-contrast `ring` or `outline` styles. Use `focus-visible:ring-inset` for containers with `overflow-hidden`. Ensure ARIA labels are updated to reflect the specific keyboard interactions provided in the `onKeyDown` handlers.
